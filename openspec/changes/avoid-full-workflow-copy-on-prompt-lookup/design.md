# Design

`PromptManager` continues to call `cache_workflow(file_name, workflow_id)` before every lookup, preserving the existing deployed-version and source behavior. An internal read-only reference selects the cached workflow group. `group_field` copies one `ExtractedField`; `group_load` copies one selected `Group`; `get_prompt` copies one selected `Prompt`. `get_fields_for_workflow` and `get_fields_for_data_object` still copy all groups when explicitly requested. No cached object escapes to a caller.

Arcadia's `RequestScopedPromptManager` still enforces the task's workflow ID and declared fields. Its generic `_deployed_group_fields` cache is redundant once SDK `group_field` is targeted, so the wrapper delegates each generic field read to the SDK. The multi-meter `_deployed_meter_fields` cache stays: it memoizes a route-to-final-field mapping, not just a copied group. Arcadia's deployed-workflow config and policy caches also stay because they own fetch/version and task metadata behavior. Charge serialization uses the existing request-scoped manager, matching meter review and avoiding repeated broad policy preparation.

The SDK edits are under `.fernignore`-protected `src/groundx/extract/`; OpenSpec is also protected. The SDK package must be released before Arcadia can adopt the new lookup behavior with its production dependency pin. A worker built with the old SDK would remain functionally correct but would regain the local copy cost. The active workflow-revision plan remains responsible for exact revision identity and authorized-client cache keys; this change does not add a cache or alter revision selection.
